## 五维度总控（全站统一）

页面顶部一条总控条，四个页面共用同一套状态。需求原文「筛选字段全部上移，总控 5 个板块」即指此。

**布局按「什么问题」分层，而不是按字段堆**——三行各问一件不同的事，同一行内的组用竖线隔开：

| 行 | 回答的问题 | 组（左标签 → 候选值） |
|---|---|---|
| **1** | 看哪段时间、怎么切 | **时间**（预设 + 起止日期）→ **粒度** → **对比**（环比 / 同比，右侧注记 `vs 对比区间`） |
| **2** | 谁在播 | **班次**（数字人 / 早 / 中 / 晚）→ **主播**（7 位真人） |
| **3** | 播的什么 | **店铺活动**（类型 › 活动名）→ **直播间机制** |

| 维度 | 取值 | 交互 |
|---|---|---|
| **时间** | 近 7 / 30 / 90 天、本月、上月、近半年、全部 + 自定义起止 | 单选 chip；起 > 止自动纠正，限制在数据范围内 |
| **班次** | 数字人 / 早 / 中 / 晚（按开播时间：00:00 数字人、09:00 早、14:00 中、19:00 晚） | 多选 + 反选，chip 后标注该班次在当前区间的场次数 |
| **主播** | 7 位真人主播 | 多选 + 反选；选中后数字人场次自动排除（无主播） |
| **店铺活动** | 类型「日销 / 活动」**›** 官方活动名（双11 / 超级88 / 618 …） | 父子结构：先选类型，活动名只列该类型下的节奏；活动名超过 5 个折成「更多 +N」，展开后整行换行铺开 |
| **直播间机制** | 无机制 / 下单加赠箱套 | 多选 + 反选 |

**为什么活动要拆成「类型 › 活动名」两级**：源表里 `rt` 与 `rn` 是一对多的父子（每个活动名只归属一个类型，实测无跨类型项）。之前把两组平铺在同一行，还各有一个「日销」候选，读起来像两个同名筛选器在打架。现在：类型组叫「不限类型」，活动名组叫「全部活动」，中间用 `›` 连接，选类型后活动名自动收窄；活动名里的「日销」显示为**日销（常规）**，与外层的类型「日销」区分开。类型切换时，已选活动名若不在新候选中会被自动剔除，不会出现选了「活动」却挂着日销活动名的空结果。

**粒度**：自动（≤45 天按日 / ≤150 天按周 / ≤400 天按月 / 更长按季）、日、周、月、季可手工锁定。趋势图与明细表同时跟随。

**对比口径**：环比（上一等长区间）与同比（去年同期同一区间）二选一作为主对比，另一个自动降为次标签，KPI 卡上两个小标签并排显示、各有文字前缀，不再挤成一个数。

> **同比的硬约束**：去年同期必须完整落在数据起点（2025-05-01）之后才给数。否则去年的窗口会和本期重叠（例如选「全部」时，去年同期是 2024-05-01~2025-11-02，其中 2025-05~11 与本期重合），算出来的是两段时间拼出来的假同比。这种情况下 KPI 显示「—」、明细同比列留空，注记写「同比期 无（去年早于数据起点）」。

**反选**：每组右侧有「反选」按钮，逻辑是「全选减当前选中」，结果为空时自动回到不限，避免出现 0 场的死状态。某组选满全部候选时自动归为「不限」，不制造假筛选。

**收起**：第 1 行右侧「收起」可折叠第 2、3 行，只留时间维度；「重置」在存在维度筛选或手工粒度时才可点。

**窄屏**：视口窄于 1360px 时首行按组整体折行，并隐藏与日期框重复的「天数 · 场次」摘要（「筛选后 X / Y」保留）；实测 1280px 下三行仍单行装下。

**联动范围**：KPI、趋势、班次、主播、目标达成、品类、单品全部跟随，且所有比率重算分子分母而非逐场平均。

**店铺侧口径提醒**：发货额 / 商品数据只有日期维度，没有班次与主播字段。启用维度筛选后，「直播渗透率」的分母仍是店铺全量，卡片上会明确标注「维度筛选时按店铺全量计」，避免被误读成同口径。

**链接可分享**：全部状态写进 URL —— `?f=起&t=止&g=粒度&c=对比&sh=班次&an=主播&rt=类型&rn=活动&mg=机制`，发出去对方打开看到同一视图。

**末尾不完整周期自动剔除**：月末 / 周末 / 季末只有几天数据时不出现在趋势图里，避免被读成断崖式下跌；明细表中仍保留该行并标注「不完整」。

## 主播页页内筛选（已并入总控）

主播页原有的「主播」「活动场次」两条页内筛选条已隐藏，功能由总控条的**主播维度**与**店铺活动维度**承接，页内不再重复一套筛选。原结构保留在 `anchor.html` 的 `.afbar`（带 `hidden`），需要回退时去掉 `hidden` 即可。


**活动名称怎么来的**：源表 V1 新增了「天猫活动节奏」逐日日历（2025-01-01 ~ 2026-11-30，699 天，含日期 / 节奏 / 类型 / 直播间机制），`build_data.py` 按日期把每场直播挂到官方节奏上，**1,795 场全部匹配，0 场落空**（10-20 连播拆分后为 1,796 条）。

名称只做归一、不改语义：

- 剔除附在名称后的券信息备注（「无消费券」「有消费券」「无消费券和限时红包」）和换行
- 去掉官方名的「天猫」前缀
- 同一活动的跨年写法合并（`618狂欢节`→`618`、`天猫新势力周`/`8月新势力周`→`新势力周`、`天猫38焕新周`→`38焕新周`），映射表在 `build_data.py` 的 `RHYTHM_ALIAS`
- 分波次/分阶段的名称保持独立（`年货节第一波`~`第四波`、`618抢先购`、`618大促520告白季`、`9月新风潮` vs `11月新风潮`），因为它们是不同活动期，合并会掩盖节奏差异

全量 32 个节奏名，场次 top：日销 425 / 618 221 / 双11 152 / 超级88 130 / 新势力周 67 / 七夕+超级88 66 / 国庆狂欢 58 / 年货节第三波 58。官方类型分布：**活动 1,228 场 / 日销 567 场**。

排班覆盖期（2026-10-01 ~ 11-02，131 场，连播拆分后 132 条）的真实节奏是：**双11 55 / 日销 28 / 国庆狂欢 24 / 10月超级88 24**（其中活动 79 场、日销 52 场；有主播的 98 场为双11 41 / 日销 21 / 国庆狂欢 18 / 10月超级88 18），不再像旧版那样全被归成一类。另有 19 场落在「直播间机制 = 下单加赠箱套」的日期上（10-20、10-21、10-31、11-01、11-02 五天）。

## 销售目标达成（分日 × 班次）

源表「天猫排班及目标表」H~K 列给了**每天四个班次（数字人 / 早 / 中 / 晚）各自的销售目标**，`build_data.py` 读成 `targets: {日期: [数字人, 早, 中, 晚]}`。

页面上分两处体现：

| 位置 | 内容 |
|---|---|
| 班次分析 · 01 班次卡片 | 每张卡底部「目标 xx万元 · N 天 / 达成 xx%」+ 进度条 |
| 班次分析 · 03 销售目标达成 | 累计目标 vs 累计实际双线图；分日 × 四班次达成率表（胶囊色阶）；合计行给出「实际 / 目标」 |
| 总览 · 04 区间明细 | 新增「目标达成」列，按当前粒度（日/周/月）汇总，悬停看实际值与目标值 |

**口径（这几条决定了数字对不对）**

1. 达成率 ＝ 成交金额 ÷ 目标，分子分母**同口径**：只统计「既有目标、又有实际」的日期。目标表覆盖 2026-10-01 ~ 11-30，但数据只到 11-02，因此 11-03 之后只有计划没有实际，一律不计入（`tgt.known()`）。
2. 目标表里没填的日子**不是目标 0**，而是「没有目标」，页面显示「无目标」，不会算出 0% 或 ∞。
3. 明细表按周/月汇总时，目标与分子都只取**该桶内的目标日**，避免拿整周成交去比只有几天的目标（否则达成率虚高）。
4. 官方目标配比是**按日总量固定权重拆分**：相对早班的比例为 数字人 0.50 / 中 0.87 / 晚 2.67（即 1 : 2 : 1.74 : 5.35），61 天里这三项比例的标准差分别为 0.011 / 0.052 / 0.267，说明是机械拆分而非逐日精算。落到结构上，晚班占目标约 68%。

**实测（2026-10-01 ~ 11-02，33 天有目标）**

| 班次 | 目标 | 实际 | 达成 |
|---|---|---|---|
| 数字人 | 38.1 万 | 26.0 万 | 68.3% |
| 早 | 74.6 万 | 67.6 万 | 90.6% |
| 中 | 146.1 万 | 109 万 | 74.4% |
| 晚 | 286.5 万 | 170 万 | 59.4% |
| **合计** | **545 万** | **372 万** | **68.3%** |

中班、晚班的差距根子在 **2026-10-20**：当天目标是双11 预售的集中投放，166.9 万里有 166.4 万压在晚班，早班、中班都是 0。当天中班与晚班是**陈思颖、赵亚男连播**，场次表只留了一条「中班 621 分钟」的记录，133.8 万全记在中班。把成交与目标都按 50:50 拆开后，中班、晚班当天各拿 66.9 万 / 83.2 万，达成率同为 80.4%。

拆分前这两个数是 279.2% 和 27.9%，拆分后收敛到 74.4% 和 59.4%，合计 68.3% 不变——拆分只改归属，不改总量。

## 连播场次怎么拆（2026-10-20）

**事实**：10-20 中班陈思颖、晚班赵亚男是连播。但场次表只留了一条记录——「中班，621 分钟」，133.8 万全记在陈思颖名下，赵亚男当天 0 场次。33 天里 32 天都是 4 场（早/中/晚/数字人），**唯独 10-20 是 3 场，缺晚班**。

排班与目标表本身是对的：早=一丹 / 中=陈思颖 / 晚=赵亚男，晚班目标 166.4 万。所以问题不在目标表，在场次表的班次归属。

**处理**：`build_data.py` 里两张表，成交和目标按同一套权重一起拆。

| 项 | 表 | 规则 |
|---|---|---|
| 成交侧 | `SPLIT_RULES` | `('2026-10-20', '中')` → 中班陈思颖 50% + 晚班赵亚男 50% |
| 目标侧 | `TARGET_SPLITS` | `('2026-10-20', '晚')` → 晚班原挂的 166.4 万拆成 中 83.2 万 + 晚 83.2 万 |
| 拆哪些字段 | — | 成交 / 退款 / 净销售 / 时长 / 观看人数 / 曝光 / 点击 / 加购 / 粉丝（体量类） |
| 不拆哪些 | — | 转化率、时均 UV、单小时 GMV 等比率——由前端用拆分后的分子分母重算，比率天然不变 |
| 守恒 | — | 成交余数补最后一条；目标只做搬迁不做增减。实测当日目标 1,669,419 元、成交 1,342,858 元，拆分前后完全一致 |

**为什么目标也要拆**：只拆成交会造成一个人「有业绩没指标」、另一个人「有指标没业绩」——陈思颖会凭空多出 66.9 万超额，赵亚男则背着 166.4 万目标只有 66.9 万成交。两边同权重拆完，当天中班、晚班达成率都是 80.4%，与当日整体 80.4% 一致。

**为什么是 50:50**：两名主播的标准班次时长是 265 / 271 分钟，按时长权重是 49.4 : 50.6，与对半的差额不到 1 万元，取整数更好解释。要改口径只改 `SPLIT_RULES` 与 `TARGET_SPLITS` 两行，重跑即生效。

**影响**：场次 1,795 → 1,796 条，有主播场次 98 → 99 条；全量成交、全量目标、班次合计达成 68.3% 都不变。

## 主播的达成率怎么归（按场承接班次目标）

目标表只有「日 × 班次」，**没有主播级目标**。主播页的做法是：把该场次所在日期、所在班次的目标，**整笔归给这一场的主播**。

这样归的依据是：排班覆盖期内，主播场次所在的「日期 + 班次」没有一场冲突（实测 0 处同日同班多场）。全量数据里同日同班多场确实存在 81 处（中 45 / 早 14 / 晚 10 / 数字人 12），但全部落在无主播场次上，因此不需要再按场次数量或时长二次拆分。

**口径**

1. 归属：`目标 = targets[日期][班次]`，`实际 = 该场成交金额`；不按小时摊、不按人数摊。
2. 当天不在目标表、或该班次目标为 0 时**不计入**——既不当 0，也不当 ∞。本区间有 2 场属于后者（10-20 早班、中班）：口径条写「2 场未计入」，卡片写「N 场当日该班次目标为 0」，矩阵里该主播的达成率带 `*`。
3. 达成率 ＝ 同口径成交 ÷ 承接目标，分子只累加有目标的场次，与分母是同一个场次集合。
4. 目标在班次间并不均分（晚班单场目标是早班的 2.7 倍），所以**绝对达成率会被排班结构带偏**。「同班次」列是校正口径：按该主播各场次目标加权，得出他所处班次结构的基准率，再用实际达成率 ÷ 基准率；`+7%` 表示比同班次整体高 7%（相对值），0% 为持平。

**实测（2026-10-01 ~ 11-02，99 场）**

| 主播 | 场次 | 承接目标 | 同口径成交 | 达成 | 同班次基准 | 相对 |
|---|---|---|---|---|---|---|
| 张洁 | 2 | 0.9 万 | 2.4 万 | 266.3% | 81.7% | +225.9% |
| 一丹 | 15 | 33.1 万 | 25.6 万 | 77.4%* | 84.0% | −7.8% |
| 陈思颖 | 24 | 154.6 万 | 119.5 万 | 77.3% | 74.4% | **+3.8%** |
| 赵亚男 | 26 | 234.8 万 | 148.8 万 | 63.4% | 59.7% | **+6.2%** |
| 刘旭 | 12 | 24.8 万 | 15.0 万 | 60.6% | 72.4% | −16.2% |
| 张文静 | 19 | 57.9 万 | 34.2 万 | 58.9% | 75.2% | −21.6% |
| 刘育 | 1 | 1.1 万 | 0.5 万 | 42.0% | 59.4% | −29.3% |
| **合计** | **99** | **507.2 万** | **345.9 万** | **68.2%** | — | — |

`*` = 该主播有场次因当日该班次目标为 0 被排除（只剩一丹 10-20 早班 4,345 元）。

两点读法：一丹绝对达成 77.4% 看着靠前，但她的场次 8 早 7 中、基准本身就有 84.0%，所以相对反而 −7.8%；张文静、刘旭绝对和相对都靠后，是这一区间真正需要复盘的人。**跨班次比人，看「同班次」列；只想知道当天完成情况，看绝对达成率。** 张洁、刘育样本 1~2 场，达成率不具代表性，矩阵里不参与「最优」评选。

主播页合计 68.2% 与班次页 68.3% 已基本对齐，差的 0.1 个点来自一丹那 4,345 元无目标场次（班次页把它算进了早班分子，主播页因该班次目标为 0 而排除）。

## 主播效率对比矩阵

把主播按列、指标按行横向铺开，每格底色表示该指标在当行 7 人中的位置：

- **金色由浅到深**＝该指标越高；**红色由浅到深**＝退款越高；**灰底**＝中性行（总时长，只作参考，不判优劣）
- 行名后的 `↑ / ↓ / ·` 标明方向；该行最优格标 `★`
- 点任意行名可按该指标重排（再点一次反向），付款率这类「越低越好」的指标会自动用升序
- 悬停任一格显示：本项数值、全员数值、相对全员的百分比
- 「排行明细」页签保留原来的 12 列精确数值表格，用于核对具体数字

## 指标口径

| 指标 | 公式 |
|---|---|
| 净销售 | 成交金额 − 退款金额 |
| 退款率 | 退款金额 ÷ 成交金额 |
| 单小时 GMV | 成交金额 ÷ 开播小时数 |
| 单小时 GSV | 净销售 ÷ 开播小时数 |
| 时均 UV | 观看人数 ÷ 开播小时数 |
| 客单价 | 成交金额 ÷ 成交人数 |
| 转化率 | 成交人数 ÷ 观看人数 |
| 加购率 | 加购人数 ÷ 观看人数 |
| 转粉率 | 新增粉丝数 ÷ 观看人数 |
| 曝光点击率 | 频道页点击人数 ÷ 频道页曝光人数 |
| **店铺发货金额** | 支付金额(全部) − 未发货仅退款 − 已收到货仅退款 − 在途仅退款 |
| **直播渗透率** | 当日直播成交金额 ÷ 当日店铺发货金额 |

所有比率均按「分子分母各自汇总后再相除」计算，**不是把每场比率取平均**，避免长短场次权重失真。

## 数据边界（重要）

1. **主播维度只覆盖 2026-10-01 ~ 2026-11-02（33 天 / 99 场）。** 因为排班表只提供 10-11 月。补更早的排班表后重跑脚本即可自动扩展，无需改代码。区间超出该范围时，主播页会提示覆盖率，不会把「无排班」显示成「业绩为 0」。
2. **数字人班次（00:00）无对应主播**，排班表只有早/中/晚三列，这是设计使然。
3. **数字人平均 12.9 小时/场，真人 4.4 小时/场**。两者单小时 GMV 不可直接比较，页面上已给出按时长归一的折算值（数字人等效约 ¥2,687/h，为真人 45%）。
4. **商品级数据按「商品 × 日」压缩存储**，因此品类与单品分析支持任意日期区间；订单明细（8,150 行 / 300 场 / 26 商品）样本不足，未做场次级商品结构分析。
5. **全店退款率 47.1%（全周期）、53.9%（近 90 天）显著偏高**。商品级支付合计与店铺日级支付合计偏差 0.00%，两个独立数据源互证通过，说明是数据本身如此，但对外引用前建议与天猫后台口径再复核。
6. 存在 29 场时长 <10 分钟、236 场 >12 小时（多为数字人挂机）的场次，已在数据中打 `flag` 标记，未做剔除。
7. **效率分布图对超大值做分位截断**：极少数单场（如 2026-10-20 中班单场 133.8 万）会把整张图压扁，因此坐标上限取 P95，超出部分钉在上边框、以虚线圈标示，并在图下注明个数与最高值，悬停可看真实值。
8. **活动名称来自官方节奏表，不是标题推断**。粒度是天，即「这一天属于哪档活动」，因此同一活动期内每场都一样；单场之间的差异（重点场 / 日常场）无法体现，也不该用标题去猜。日历覆盖 2025-01-01 ~ 2026-11-30，源表未覆盖到的日期若出现场次会落到「日销」，重跑时 `meta.rhythmMiss` 会报未匹配场次数（当前 0）。
9. **销售目标只有 2026-10-01 之后**。更早的区间一律显示「无目标」，不补造历史目标，也不拿 0 当目标。
10. **主播的达成率不是官方主播级目标**。目标表只到「日 × 班次」，主播页按「该场次所在日期与班次」整笔承接，因此同一班次换谁播，承接的目标是一样的；它衡量的是「这个人把这一班的目标完成得怎样」，不是公司给某位主播单独下的指标。
11. **10-20 的连播是人工拆分，不是源表自带**：场次表只有一条中班记录，中班与晚班的成交、目标都按 50:50 拆。50:50 是中性假设，不是从数据里算出来的真实贡献比；真实贡献只有当事主播和运营知道。要改成别的比例，同时改 `SPLIT_RULES` 与 `TARGET_SPLITS` 的权重（两处必须一致，否则业绩与指标会错配）后重跑即可，其余逻辑不用动。
